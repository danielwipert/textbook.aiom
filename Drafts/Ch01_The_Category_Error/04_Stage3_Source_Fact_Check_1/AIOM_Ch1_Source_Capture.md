# Chapter 1: source capture worksheet

Standard: Decision 40, Option C. For every source, select the most durable
available form, capture to Perma.cc and to the Wayback Machine, file a local
copy, and record the fields below.

Work top to bottom. The three upgrades come first, because upgrading changes
what gets captured.

---

## Upgrade first, then capture

### 1. Microsoft, 4.7 million Copilot subscribers

Currently cited to the FY26 Q2 earnings call, January 28, 2026.

This number is load-bearing and should rest on a filing rather than a call.
Check, in this order:

1. The 10-Q for the quarter ended December 31, 2025, on SEC EDGAR. If the figure
   appears there, cite the filing and nothing else needs archiving, because
   EDGAR is permanent.
2. Any 8-K exhibit carrying the prepared remarks.
3. Failing both, Microsoft's own transcript on its investor relations site, which
   then does need capture.

Record: filing type, filing date, accession number, and the page or section
carrying the figure.

### 2. GitHub billing documentation

`docs.github.com` is published from a public repository, so the billing pages
have a commit history. Cite a specific permalinked revision rather than the live
page. This pins the exact text relied on, which is stronger than an access date
on a page that will read differently next year.

Record: the permalink to the revision, and the commit date.

Applies to both GitHub entries, the June 18, 2025 premium-request billing change
and the April 27, 2026 usage-based billing announcement.

### 3. Altman post on X, January 5, 2025

The weakest link in the chapter and the one carrying the most argumentative
weight. X has broken old links and API access repeatedly.

Do both:

1. Capture the post itself to Perma.cc and Wayback.
2. Add a second path to the same claim: a reputable published account that
   reproduced the statement, cited with Chicago's "quoted in" construction.

Two independent paths is the standard for anything perishable and load-bearing.

Record: the canonical post URL, both archive links, and the full citation for
the secondary account.

## Note on the access dates currently in the chapter

The register presently reads "Accessed July 28, 2026" throughout. That records
verification against the live record, not capture. Once capture happens, the
dates should be reset to the true capture dates, and the archive links added.

Until then the register overstates what has been done, and Chapter 1 cannot pass
G1.
